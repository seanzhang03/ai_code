# 对话上下文优化方案（三种方案的完整代码）

> 本文件汇总三种优化方案**需要修改**和**需要新增**的全部代码，可直接按文件路径落地。参数统一做成 `.env` 可配，默认：条数上限 M=50、滑动窗口保留 N=5 轮、每 K=5 轮做一次摘要。

---

## 0. 项目现状（为什么要优化）

- `my_rag_project` 是 FastAPI 分层（controller → service → dao → entity）的 RAG 问答项目，MySQL 用原生 pymysql（无 ORM）。
- `chat/service/ChatService.py` 当前把某窗口**全部历史**查出来拼进 prompt，**没有任何**截断 / 条数限制 / 摘要。对话一长，prompt 就越长、越容易超 token 上限、越慢越贵。
- `history` 表结构：`history_id`(自增PK) / `users_id` / `question` / `answer` / `parent_id` / `create_time`。一个"对话窗口" = 一条 `parent_id=0` 根记录 + 若干 `parent_id=根id` 子记录；每条记录 = 一轮问答。
- 保存由前端单独调 `/history/saveChatResult`；`chat` 只读不写。
- 主 LLM：通义千问（`common/LoadLLM.py`，ChatOpenAI 兼容，`streaming=True`）。

## 2. 方案一：限制对话次数（上下文条数上限 M）

**思路**：存储层不动（仍全部入库、可回溯），只在**组装上下文时**截断——最多取最近 `M=50` 条，更早的不进模型。

**修改文件**：`chat/service/ChatService.py`

> 顶部加：

```python
import os
from dotenv import load_dotenv
load_dotenv()

MAX_HISTORY_RECORDS = int(os.getenv("MAX_HISTORY_RECORDS", "50"))
```

> `chat()` 里查到历史后加一行截断（升序列表取末尾 M 条 = 最新 M 条）：

```python
def chat(question:str, historyId:int):
    llm = LoadLLM().llm
    history_data = HistoryDao.query_history_list_by_historyid(historyId)

    # —— 方案1：只保留最近 MAX_HISTORY_RECORDS 条，更早记录不进上下文 ——
    history_data = history_data[-MAX_HISTORY_RECORDS:]

    chat_history_list = []
    for item in history_data:
        chat_history_list.append({"role":"user","content":item["question"]})
        chat_history_list.append({"role":"assistant","content":item["answer"]})
    # ... 后续意图识别 / 两条分支逻辑不变 ...
```

**特点**：最简单，一行切片；缺点：超过 50 条的老对话语义彻底丢失。

## 3. 方案二：滑动窗口（截取最近 N 轮）

**思路**：以"轮数"为窗口（1 条记录 = 1 问 1 答 = 1 轮），每次只取最近 `N=5` 轮，前期直接忽略。即 `history_data[-N:]`。

## 4. 方案三：总结摘要（摘要表持久化 + 每 K 轮摘要 + 保留近 N 轮）

**思路**：早期对话折叠成摘要，模型上下文 = `[早期摘要] + [最近 N 轮完整]`，防止语义丢失。摘要单独建表，用 `user_id + history_id`（窗口根 id）合并标识，每 `K=5` 轮滚动生成/更新一次。

### 4.1 建表 DDL（手动在 MySQL 执行）

**新增 SQL**（执行一次）：

```sql
CREATE TABLE `history_summary` (
  `summary_id`      INT AUTO_INCREMENT PRIMARY KEY,
  `users_id`        INT  NOT NULL,                 -- 用户id（合并标识之一）
  `history_id`      INT  NOT NULL,                 -- 对话窗口根id（parent_id=0 那条的 history_id，合并标识之二）
  `summary`         TEXT NOT NULL,                 -- 早期对话的摘要文本
  `last_history_id` INT  NOT NULL DEFAULT 0,       -- 摘要已覆盖到哪条 history_id（增量摘要游标）
  `create_time`     DATETIME DEFAULT NULL,
  `update_time`     DATETIME DEFAULT NULL,
  UNIQUE KEY `uk_user_window` (`users_id`, `history_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 新增 `summary/dao/SummaryDao.py`

**新增文件**：`my_rag_project/summary/dao/SummaryDao.py`（同目录需有 `__init__.py`）

```python
from common.LoadMySQLConn import LoadMySQLConn

# 查询某个窗口的摘要（按 user_id + history_id）
def query_summary(usersId:int, historyId:int):
    conn = LoadMySQLConn().conn
    cursor = conn.cursor()
    sql = "SELECT summary, last_history_id FROM history_summary WHERE users_id=%s AND history_id=%s"
    cursor.execute(sql,[usersId,historyId])
    result = cursor.fetchone()
    LoadMySQLConn().close_mysql_conn(cursor,conn)
    return result

# 插入或更新摘要（user_id+history_id 已存在则更新）
def upsert_summary(usersId:int, historyId:int, summary:str, lastHistoryId:int):
    conn = LoadMySQLConn().conn
    cursor = conn.cursor()
    try:
        sql = """
            INSERT INTO history_summary (users_id, history_id, summary, last_history_id, create_time, update_time)
            VALUES (%s,%s,%s,%s,now(),now())
            ON DUPLICATE KEY UPDATE summary=VALUES(summary), last_history_id=VALUES(last_history_id), update_time=now()
        """
        cursor.execute(sql,[usersId,historyId,summary,lastHistoryId])
        conn.commit()
        return cursor.rowcount
    except Exception as e:
        print(f"异常原因:{e}")
        conn.rollback()
        return 0
    finally:
        LoadMySQLConn().close_mysql_conn(cursor,conn)
```

### 4.3 新增 `summary/service/SummaryService.py`

**新增文件**：`my_rag_project/summary/service/SummaryService.py`

```python
import os
from dotenv import load_dotenv
load_dotenv()

from common.LoadLLM import LoadLLM
from summary.dao.SummaryDao import query_summary, upsert_summary
from history.dao import HistoryDao

RECENT_ROUNDS      = int(os.getenv("RECENT_ROUNDS", "5"))      # 保留最近 N 轮完整
SUMMARY_INTERVAL   = int(os.getenv("SUMMARY_INTERVAL", "5"))   # 每 K 轮做一次摘要

# 调用主 LLM 生成一段摘要
def _generate_summary(text:str) -> str:
    llm = LoadLLM().llm
    prompt = f"""
        你是一个对话摘要助手。请把下面这段历史对话压缩成一段简明摘要，保留关键信息：
        （用户持续关心的问题、已经确认的结论、重要实体如电影名/导演/主演/日期/评分等），
        去掉寒暄和冗余表述，保持要点可被后续对话引用。
        只输出摘要正文，不要任何解释。
        历史对话：
        {text}
    """
    return llm.invoke(prompt).content.strip()

# 保存一条记录后调用：判断是否滚动生成/更新摘要（增量式）
def maybe_summarize(userId:int, historyId:int):
    records = HistoryDao.query_history_list_by_historyid(historyId)  # 升序：根 + 子
    if len(records) < RECENT_ROUNDS + SUMMARY_INTERVAL:
        return  # 记录数还不够触发摘要

    early_records = records[:-RECENT_ROUNDS]            # 早期 = 去掉最近 N 轮
    row = query_summary(userId, historyId)
    last_summarized_id = row["last_history_id"] if row else 0

    new_early = [r for r in early_records if r["history_id"] > last_summarized_id]
    if len(new_early) < SUMMARY_INTERVAL:
        return  # 未达到触发间隔

    # 旧摘要 + 新增早期记录 → 增量合并后重新摘要
    prev_summary = row["summary"] if row else ""
    text = "\n".join(f"用户：{r['question']}\nAI：{r['answer']}" for r in new_early)
    merged = (prev_summary + "\n") if prev_summary else ""
    merged += text
    new_summary = _generate_summary(merged)

    new_last_id = new_early[-1]["history_id"]          # 更新游标到本次纳入的最后一条早期记录
    upsert_summary(userId, historyId, new_summary, new_last_id)
```

### 4.6 `chat/service/ChatService.py` 组装「摘要 + 近 N 轮」

**修改文件**：`my_rag_project/chat/service/ChatService.py`

```python

from dotenv import load_dotenv
```

> `chat()` 里原来「查历史 + 拼 chat_history_list」的循环段，替换为：

```python
def chat(question:str, historyId:int):
    llm = LoadLLM().llm
    history_data = HistoryDao.query_history_list_by_historyid(historyId)

    # —— 方案3：摘要 + 滑动窗口组装上下文 ——
    users_id = HistoryDao.query_usersid_by_historyid(historyId)   # 取窗口所属用户
    summary_row = query_summary(users_id, historyId) if users_id else None

    chat_history_list = []
    # 1) 先放早期对话摘要（作为 system 提示）
    if summary_row and summary_row["summary"]:
        chat_history_list.append({"role":"system", "content":f"此前对话的摘要：{summary_row['summary']}"})
    # 2) 再放最近 N 轮完整记录
    recent = history_data[-RECENT_ROUNDS:] if len(history_data) > RECENT_ROUNDS else history_data
    for item in recent:
        chat_history_list.append({"role":"user","content":item["question"]})
        chat_history_list.append({"role":"assistant","content":item["answer"]})

    # ... 后续意图识别 / 两条分支逻辑保持不变 ...
```

**特点**：最完整，兼顾 token 与语义——早期语义靠摘要保留、近期细节靠 N 轮完整兜底、摘要跨请求持久化增量更新。代价是复杂度最高，摘要那一步有额外 LLM 调用（同步在保存接口里，会略微增加保存耗时，可后续改后台任务）。

## 5. 三种方案对比

| 方案 | 改动量 | 语义保留 | 额外 LLM 调用 | 适用场景 |
|---|---|---|---|---|
| 一 条数上限 | 最小（1 文件 1 行） | 差（超限全丢） | 无 | 快速止血、只想限 token |
| 二 滑动窗口 | 小（1~2 文件） | 差（早期全丢） | 无 | 简单稳定、短会话 |
| 三 总结摘要 | 较大（建表 + 2 新文件 + 3 改文件） | 好（早期浓缩保留） | 每 K 轮 1 次 | 追求质量、长会话 |

## 6. 组合落地建议

三者可以**叠加**成一套完整策略（最常用）：摘要解决"早期语义"、滑动窗口解决"近期细节"、条数上限兜底"极端长度"。

实际落地最省事的是 **方案三（已内置近 N 轮）+ 方案一的条数上限兜底**：在 4.6 的上下文组装后，再加一次 `history_data = history_data[-MAX_HISTORY_RECORDS:]` 即可。也可以只上方案二快速解决当下 token 压力。

1. **建表**：MySQL 执行 4.1 的 DDL；`.env` 填入三个参数。
2. **启动**：`python main.py`（内嵌 uvicorn，localhost:8000）。

4. **断言**：
   - 方案一：`chat()` 里 `history_data` 长度 ≤ 50。
   - 方案二：`history_data` 只剩最近 5 条（升序）。
   - 方案三：`history_summary` 表在同一窗口达到 10 轮后出现一行、`summary` 非空、`last_history_id` 等于倒数第 6 条记录的 id；且 `chat_history_list` 头部是 system 摘要、尾部是最近 5 轮。
